v1.1.0 Stable Release March 2026

Security & Privacy

  • In-file metadata stripping — DOCX files now have docProps/core.xml and docProps/app.xml replaced with blank versions before storage, removing Author, Last Modified By, Company, and revision history. All ZIP entry timestamps are also zeroed. PDF files have their /Info dictionary values and XMP metadata packet cleared.
  • HMAC integrity hash — integrity_hash is now HMAC-SHA256 keyed with a sub-key derived from ENCRYPTION_KEY rather than raw SHA-256. This prevents the stored hash from being looked up in public content-addressable databases (VirusTotal, NSRL, etc.) to trace the original uploader.
  • upload_log short_id removed — the daily rate-limit log no longer stores which specific file was uploaded per pseudonymous user tag. A database leak can no longer reconstruct which user uploaded which file from the rate-limit table.
  • Security headers added — all server responses now include Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff, X-Frame-Options: DENY, and Permissions-Policy disabling camera, microphone, geolocation, and payment.
  • localStorage auto-purge — upload history entries are now removed after 30 days regardless of their expiry date, limiting the permanent paper trail on the uploader's device. Stale owner_* delete tokens are also purged on startup.

Bug Fixes

  • Upload quota bypass closed — daily upload count now persists after file deletion. Previously, uploading and immediately deleting a file restored the quota slot, allowing the 5-files/24h limit to be bypassed indefinitely. The upload_log entry is now intentionally kept on deletion. #14
  • DOCX files now render in the viewer — Word documents previously showed "this file can't be opened" because no DOCX renderer existed. Mammoth.js is now used to convert DOCX to styled HTML client-side, with full dark-mode support and screenshot protection applied.
  • /api/mode 404 on Cloudflare Pages fixed — the self-host detection endpoint only existed in the Express server. A Cloudflare Pages Function at functions/api/mode.js now returns {"{"}"selfHostMode": false{"}"}, eliminating the 404 console error on hosted deployments.
  • Null TypeError after file deletion fixed — the delete handler previously replaced the entire result card's HTML, destroying cached element references. The next upload would crash with Cannot set properties of null (setting 'href'). The handler now transitions cleanly back to the upload card without destroying the DOM structure.

Features

  • Screenshot protection badge — a visible "Protected" indicator now appears in the viewer topbar so users can confirm screenshot protection is active. #12 #16
  • CSS content protection — user-select: none and -webkit-touch-callout: none added to PDF pages, images, and text content to prevent text selection and long-press save on mobile. #12
  • "Report an Issue" link — added to footers on the main app and viewer pages, linking directly to the GitHub Issues tracker. #15
  • Public changelog — this page. All releases documented in one place, accessible at /changelog.
  • wrangler.toml.example — Cloudflare Pages deployment config template added. The real wrangler.toml remains gitignored; the example guides users through all required variables without exposing credentials.

Docs & Legal

  • README rewritten — feature table, badges, cleaner architecture diagram, consolidated self-hosting guide, quick troubleshooting table, legal notice.
  • Terms & Conditions strengthened — zero-liability language now explicitly covers content uploaded, stored, transmitted, shared, and sent to other people. Section 3.2 expanded with a full bulleted list of user responsibilities. Section 9 (Limitation of Liability) extended to cover third-party harm and what others receive.
  • Security policy updated — removed "Dev Testing" badge and dev-build warnings. docs/SECURITY.md rewritten with accurate feature descriptions (removed incorrect JWT reference from original).

Housekeeping

  • Removed public/index_old.html — legacy upload page no longer needed.
  • Removed public/SecureShare.png — old branding asset superseded by ShareSecure.png.
v1.0.x Patch Series March 2026

Features

  • Self-host admin mode — server detects self-hosted deployments via /api/mode and exposes an admin UI that bypasses authentication, showing upload history and unlimited quota.
  • Document rename — uploaders can set a custom display name for their document before sharing. The original filename is preserved server-side; the display name is used in the viewer and dashboard.
  • Enhanced screenshot protection — document blanks on visibilitychange (tab hidden, app switcher) and window.blur (focus lost to another app), providing Snapchat-style blackout behaviour.
  • Upload count display — dashboard now shows authoritative "Used X/5 today" count fetched from the server's upload_log, surviving localStorage clears.

Security & Privacy

  • Forward secrecy for stored files — per-file key wrapping introduced. Each file is encrypted with a unique ephemeral key; only the wrapped key is stored. Compromise of one file's key does not compromise others.
  • DOCX container validation — ZIP magic bytes are no longer sufficient. DOCX uploads must contain a valid word/document.xml entry, closing the gap where any .zip could pass as a Word document.
  • Session privacy — authentication tokens are stateless base64 credentials (no session storage server-side). Upload history moved entirely to localStorage — no server-side user→file association.
  • Pseudonymous rate limiting — upload rate limits now use an HMAC-SHA256 derived tag instead of raw user IDs. A full database leak cannot link rate-limit records to a specific account.
  • IP address stripping — forwarding headers (X-Forwarded-For, CF-Connecting-IP, etc.) are stripped at the middleware layer before reaching any route handler.
  • Encryption key management documented — security policy updated to recommend injecting ENCRYPTION_KEY via environment variables or a secrets manager rather than co-locating it with the database.
v1.0.0 Initial Release February 2026

Initial Features

  • Encrypted ephemeral file sharing — upload PDF/DOCX, receive a short-lived encrypted link. Files auto-delete in 1 minute to 24 hours.
  • Untraceable resharing — every recipient gets an independent link with no parent-child database linkage.
  • AES-256-GCM encryption at rest with SHA-256 integrity verification on every access.
  • Magic byte validation — file type determined by binary signature, not filename or MIME header.
  • PDF annotations — pen, highlighter, text, eraser tools. Annotations encrypted and isolated per-link.
  • QR code generation — fully client-side, no third-party calls.
  • Optional download toggle — uploader controls whether recipients can download the file.
  • Authentication system — optional account registration for tracked upload history and daily quota.
  • Self-hosting support — full Node.js/Express server with SQLite, localtunnel, and configurable encryption key.
  • Cloudflare Pages deployment — serverless variant using Turso/libSQL for edge-hosted database.
