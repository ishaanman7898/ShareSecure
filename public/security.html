Security

Last updated September 23, 2026

Reporting a problem

If you find a security issue, email ishaanmanoor1@gmail.com instead of opening a public GitHub issue. Say what's affected, how to reproduce it, and what someone could do with it. We'll reply as soon as we can and let you know when it's fixed.

How files are protected

  • Encrypted storage. Files, their names and notes are encrypted with AES-256-GCM, each with its own key derived from a server master key.
  • Links that expire. You pick 1 hour to 10 days. After that the link stops working and the file is erased.
  • Not indexed. Pages tell search engines not to index or cache them, can't be embedded in other sites, and aren't cached by your browser.
  • No tracking. No analytics or third-party scripts, and ShareSecure's code doesn't log IP addresses.

What it doesn't protect against

  • The server operator. Encryption uses a key held on the server, so it isn't end-to-end. Whoever runs the server could read files while they exist. For sensitive files, run ShareSecure yourself.
  • Anyone with the link. A link is all it takes to open a file until it expires. Share links privately and pick the shortest expiry that works.
  • Your network. Your internet provider and the hosting company can see that you connected. Use Tor or a VPN if you need to hide that.
  • The person you share with. They can screenshot or photograph a file even when downloads are turned off.

Good habits

  • Use the shortest expiry you can.
  • Delete a share from Your shares as soon as it's been opened.
  • Send links through private messages, not public channels.
